# Blinko Feature Plan: Email-to-Note & Reminders

## Feature 1: Email-to-Note (IMAP Polling)

### Overview
Admin configures IMAP credentials in settings. A background job polls for new emails and converts them into notes with attachments.

### 1.1 Database & Config Changes

**`shared/lib/types.ts`** — Add IMAP config keys to `ZConfigKey` (after line 106):
```ts
z.literal('imapHost'),
z.literal('imapPort'),
z.literal('imapUser'),
z.literal('imapPassword'),
z.literal('imapFolder'),
z.literal('imapPollInterval'),
z.literal('imapEnabled'),
z.literal('imapAutoTag'),
```

**`prisma/schema.prisma`** — No new tables needed. Config keys use existing `config` table.

### 1.2 New Dependencies
```bash
bun add imap-simple mailparser turndown
```
- `imap-simple` — IMAP connection + IDLE/polling
- `mailparser` — Parse email headers, body, attachments
- `turndown` — HTML → Markdown conversion

### 1.3 Server: Email Poll Job

**Create `server/jobs/emailPollJob.ts`** extending `BaseScheduleJob`:
- `taskName = 'email-poll'`
- `cronSchedule = '*/5 * * * *'` (every 5 min, configurable)
- `RunTask()`:
  1. Read IMAP config from `adminCaller.config.list()`
  2. If `imapEnabled !== true`, return early
  3. Connect to IMAP server via `imap-simple`
  4. Search for unseen messages in configured folder
  5. For each email:
     a. Parse with `mailparser` → subject, from, htmlBody, attachments
     b. Convert HTML body to markdown via `turndown`
     c. Format note content: `## {subject}\n\n**From:** {from}\n**Date:** {date}\n\n{markdownBody}`
     d. Save attachments via `FileService.uploadFile({ buffer, originalName, type, accountId })`
     e. Create note via `userCaller(ctx).notes.upsert({ content, type: 1, attachments: [...] })`
     f. If `imapAutoTag` configured, the hashtag in content handles auto-tagging
     g. Mark email as seen in IMAP
  6. Disconnect from IMAP
- Store last-processed UID in config key `imapLastUid` to avoid re-processing

### 1.4 Server: Job Registration

**`server/index.ts`** — Add to `initializeJobs()`:
```ts
import { EmailPollJob } from './jobs/emailPollJob';
// ...
await EmailPollJob.initialize();
```

### 1.5 Frontend: Email Settings Panel

**Create `app/src/components/BlinkoSettings/EmailSetting.tsx`** following `StorageSetting.tsx` pattern:
- Toggle: Enable/Disable IMAP polling
- Fields: IMAP Host, Port, Email, Password (use `PasswordInput` component), Folder, Poll Interval
- Field: Auto-tag name (optional — email notes get `#email` or custom tag)
- Save button → `api.config.update.mutate({ key, value })` for each field
- "Test Connection" button → new tRPC procedure that attempts IMAP connection

**Register in settings page** — Add `EmailSetting` component to wherever settings panels are rendered (likely a settings page that imports all `BlinkoSettings/*` components).

| File | Action |
|------|--------|

| `server/jobs/emailPollJob.ts` | **Create** — IMAP poll job |

## Feature 2: Note Reminders

### Overview
Users set a reminder time on any note. A background job checks every minute and creates in-app notifications for due reminders.

### 2.1 Database Changes

**`prisma/schema.prisma`** — Add `remindAt` field to `notes` model (after line 88):
```prisma
remindAt       DateTime?       @db.Timestamptz(6)
```

Run migration:
```bash
bun run prisma:migrate:dev --name add-note-reminders
```

### 2.2 Notification Type Extension

**`shared/lib/prismaZodType.ts`** — Add `REMINDER` type (line 243):
```ts
export const NotificationType = {
  FOLLOW: 'follow',
  COMMENT: 'comment',
  SYSTEM: 'system',
  REMINDER: 'reminder',
} as const
```
The `notificationType` z.union already has `z.string()` fallback, so this is additive.

### 2.3 Server: Reminder Check Job

**Create `server/jobs/reminderCheckJob.ts`** extending `BaseScheduleJob`:
- `taskName = 'reminder-check'`
- `cronSchedule = '* * * * *'` (every minute)
- `RunTask()`:
  1. Query: `prisma.notes.findMany({ where: { remindAt: { lte: new Date() }, isRecycle: false, isArchived: false } })`
  2. For each due note:
     a. Create notification: `CreateNotification({ type: 'reminder', title: 'note-reminder', content: note.content.substring(0, 100), metadata: { noteId: note.id }, accountId: note.accountId })`
     b. Clear the reminder: `prisma.notes.update({ where: { id: note.id }, data: { remindAt: null } })`
  3. Return count of notifications created

### 2.4 Server: Extend Note Upsert

**`server/routerTrpc/note.ts`** — In the upsert input schema (line 841), add:
```ts
remindAt: z.date().nullable().optional(),
```

In the create/update logic, pass `remindAt` through to prisma.

### 2.5 Server: Snooze Endpoint

**`server/routerTrpc/note.ts`** — Add a `snooze` procedure:
```ts
snooze: authProcedure
  .input(z.object({ id: z.number(), minutes: z.number() }))
  .mutation(async ({ input, ctx }) => {
    const remindAt = new Date(Date.now() + input.minutes * 60 * 1000);
    return prisma.notes.update({ where: { id: input.id }, data: { remindAt } });
  })
```

### 2.6 Server: Job Registration

**`server/index.ts`** — Add to `initializeJobs()`:
```ts
import { ReminderCheckJob } from './jobs/reminderCheckJob';
// ...
await ReminderCheckJob.initialize();
```

### 2.7 Frontend: Reminder Dialog

**Create `app/src/components/BlinkoCard/ReminderDialog.tsx`**:
- Triggered from BlinkoCard right-click menu or a clock icon button
- Uses HeroUI `DatePicker` component (already a dependency via @heroui/react)
- Shows date+time picker, "Set Reminder" button
- Calls `api.notes.upsert.mutate({ id, remindAt: selectedDate })`
- When reminder is active, shows a small clock icon on the card with tooltip

### 2.8 Frontend: Notification Handling

**`app/src/components/BlinkoNotification/index.tsx`** — Extend to handle `reminder` type:
- Add icon: `mdi:bell-ring-outline` for REMINDER type
- On click: navigate to the note (open in editor)
- Show "Snooze" dropdown: 10 min, 1 hour, Tomorrow
  - Calls `api.notes.snooze.mutate({ id: noteId, minutes })`

### 2.9 Frontend: Card UI Update

**`app/src/components/BlinkoCard/index.tsx`** — Show reminder indicator:
- If `note.remindAt` is set and in the future, show a small clock icon badge
- Tooltip shows "Reminder: {formatted date}"
- Click to edit/cancel reminder

## Implementation Order

1. **Reminders first** — smaller scope, no new dependencies, immediate value
2. **Email-to-Note second** — requires npm packages, IMAP complexity

3. Wait → notification appears in bell icon
4. Click notification → opens note
5. Test snooze → notification rescheduled
